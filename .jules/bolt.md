## 2025-06-10 - Dashboard N+1 & Backend Filtering Bottlenecks
**Learning:** The dashboard exhibited two major performance anti-patterns: 1) A client-side N+1 bottleneck where detailed visit summaries were fetched for every vehicle on initial mount, regardless of visibility. 2) A backend 'filter-in-app' pattern where the statistics endpoint fetched all historic transactions to calculate monthly totals in Python. Additionally, in large components like `Dashboard.jsx`, React state hooks and helper functions must be declared before any `useEffect` or `useMemo` that consumes them to avoid ReferenceErrors caused by the Temporal Dead Zone (TDZ).

**Action:** 1) Implement lazy loading for secondary data (like vehicle summaries) triggered by UI actions (expansion). 2) Push date-filtering logic to the database layer (Supabase `gte`/`lte`) to reduce payload size. 3) Always hoist stateless helpers outside the component and ensure state-dependent hooks follow a strict declaration-before-usage order.
